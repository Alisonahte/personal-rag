# 两个项目，一晚上从“听过”到“能演示、能解释”

不要把目标定成背完所有名词。目标是：不用看稿画出流程、现场跑通、改一个需求、定位一个失败。任何人都无法保证一晚上应对所有面试追问；遇到没有实现的内容，说明边界和下一步设计，比编造更可信。

## 0. 两个项目到底在干什么

**CodeGuide：给大模型配一套操作项目的手脚和规则。**
用户说“修复加法函数”。模型先请求读文件；程序检查权限后读文件，把内容回传；模型决定改哪里；程序展示修改并审批；修改后执行测试，把测试结果再交给模型。循环直到结束。

**Personal RAG：让模型开卷答题。**
你上传课程资料，程序先切成小段、做向量索引。提问时找到最相关的几段，让模型只根据这些段落组织答案，并显示出处。它没有训练或修改模型参数。

区别：第一个模型决定下一步操作，流程长度不固定；第二个先检索再生成，流程预先确定。因此第二个目前是 RAG 应用，不是自主 Agent。

## 2. 先建立最重要的知识框架

### LLM / Token / Context
LLM 像会读写的实习生。Token 是它计算文字的单位，不等于汉字或单词。Context 是这次发给它的全部材料。普通聊天 API 并不会自动记住你上一次说的话，客户端通常要把历史重新发过去。

记忆句：**模型负责生成，程序负责记忆和执行。**

### Prompt / Message
Prompt 是给模型的说明。消息列表通常包含 system（规则）、user（任务）、assistant（模型回答/工具请求）、tool（工具结果）。规则不能代替权限校验；文档里的“忽略前面指令”只是待处理数据。

### Function Calling / Tool Calling
不是模型直接调用 Python 函数。模型生成结构化请求，例如：

```json
{"name":"read_file","arguments":{"path":"calculator.py"}}
```

宿主解析参数→查工具注册表→校验→检查权限→执行函数→把结果作为 tool 消息送回。JSON Schema 描述参数形状，不保证参数安全或业务正确。

### ReAct
可以记成“决定下一步→行动→看结果→再决定”。不需要打印模型内部推理才能叫 ReAct；工程上关注可观察的工具动作和结果。

```python
while steps < limit:
    reply = model(messages, tools)
    messages.append(reply)
    if not reply.tool_calls:
        break
    for call in reply.tool_calls:
        result = validate_approve_and_execute(call)
        messages.append(tool_message(call.id, result))
```

这是理解用伪代码，真实实现还有流式事件、重试、取消、异常和持久化。

### Agent Harness
Harness 原意像驾驭工具的一套装具。这里指模型外面的运行设施：调度循环、工具、权限、记忆、上下文、日志、UI、评测。不是另一个大模型。

记忆句：**LLM 是脑，工具是手，Harness 是工作台、规则和记录。**

### async/await
等待网络或磁盘时让出执行权。不是自动多线程，也不是所有操作自动变快。阻塞的 requests/subprocess 直接放进 async 函数会卡事件循环；本项目命令执行用了 asyncio.to_thread，FastAPI 上传处理也移到了线程池。

### Event 与 Hook
Event 像广播“工具开始了”，负责展示和记录；Hook 像闸门“先判断能不能执行”，可以拦截或改参数。把两者混在一起，会让日志代码意外影响业务流程。

### JSON / JSONL / JSON-RPC 2.0
JSON 是数据格式。JSONL 是每行一个 JSON，适合逐条写会话。JSON-RPC 是调用约定，例如：

```json
{"jsonrpc":"2.0","id":7,"method":"prompt","params":{"text":"解释这个项目"}}
```

这只是格式示意，实际 method 和参数请看桥接源码。响应带同一个 id；没有 id 的通知通常不要求响应。它不是 HTTP，也不是 MCP；协议可以跑在进程标准输入输出上。若 stdout 用来传 JSON，普通调试日志应写 stderr，避免破坏协议。

### TypeScript / Node / Python
TypeScript 是带类型检查的 JavaScript，通常编译后由 Node 运行。上游 TUI 用它处理键盘、布局、流式展示；Python 负责模型和 Agent 逻辑。两者通过 JSON-RPC 通信。新增教学入口是纯 Python CLI，原始 TUI 是另一个入口。

### pytest / Fake / Mock
测试是可执行的预期。“模型替身”按脚本返回请求，让测试不花 API 钱、每次结果稳定。它只能证明程序调度正确，不能证明模型聪明或模型真实调用成功。

### Docker
把运行环境和依赖装进镜像，容器由镜像启动。容器隔离强度取决于配置；挂载整个用户目录、特权模式或 Docker socket 都会扩大权限。写了 Dockerfile 不等于完成安全沙箱。

简历应写“基于 my-pi-agent 二次开发”，随后准确描述新增路径限制、权限审批、步数限制与测试。

### 如果真正从空白写，按这七步
1. 定义 Message、ToolCall、ToolResult，只做一种模型接口。
2. 写 read_file，并给它 JSON Schema；先验证程序能按参数执行。
3. 写上面的 while 循环，用假模型测试“读→结果→结束”。
4. 加 write_file、search_code、run_command；拒绝默认拒绝，不靠字符串黑名单判断命令安全。
5. 每条消息落 JSONL；重启读回来。再给记录加 id 和 parent_id，支持分支。
6. 模型上下文预算不足时保留最近消息，对早期完整轮次生成摘要；原始日志仍保留。
7. 加事件流，再做 UI 和 RPC；不要第一小时就写复杂终端界面。

本项目走的是复用上游 1/3/5/6/7，新增可讲清楚的第 4 步和限制措施。

### 一次完整执行的数据流
“修复 calculator.add”→CLI 生成 user 消息→Agent 形成上下文→DeepSeek 返回 read_file 请求→工具读到 `return a-b`→结果携带工具调用 ID 回传→模型请求 write_file→展示内容等待 yes→写成 `return a+b`→模型请求运行 pytest→批准→真实测试输出→模型解释结果。

如果写入被拒绝：返回工具错误，模型可以解释或换方案；不能假装已经写入。
如果测试失败：exit_code 不为 0，输出回到模型，模型需要再定位；“命令执行成功”不等于“测试通过”。

### 为什么每次工具结果要对应 call ID
模型可能一次要求两个工具。id 像取餐号，返回结果必须知道属于哪个请求。取消、压缩、重试时如果留下一个请求却删掉结果，会导致历史不合法或模型误解。上游专门有工具历史修复和防孤儿调用测试。

### 会话树通俗解释
对话 A→B→C。你回到 B 换一种方案，形成 A→B→D，C 仍保留。current_id 指向当前分支，构造上下文只取根到当前节点的路径。**回退会话不等于恢复磁盘文件。**要恢复文件仍需 Git diff/checkout、快照或备份机制。

### 上下文压缩不是删聊天记录
原始记录保留；给模型看的视图变成“早期摘要+近期完整对话”。摘要可能丢失细节，需要保留目标、约束、已修改文件、测试结果和未解决问题。不能在工具调用/结果中间硬切一刀。

### 安全边界必须能说出来
- WorkspacePolicy 先解析规范路径，再判断是否位于项目根内；还拒绝 .env/.git 等路径。
- 命令工具 shell=False，避免额外 shell 解析，但 Python 或测试文件本身仍能做任意操作。
- cwd 只是工作目录，不是沙箱。人工批准后命令拥有当前用户权限。
- TOCTOU：检查路径之后、打开之前路径可能被恶意改掉；当前原型没有消除这一竞态。
- subprocess timeout 不能证明所有孙进程都被可靠回收，这是后续要改的点。
- 原始 TUI 并不自动使用新增 CodeGuide 权限策略，不要混淆两个入口。

## 4. RAG 从零怎么搭

### 最好记的比喻
资料很多，不能把整座图书馆塞给模型。先把书切成卡片，给卡片做“语义坐标”，问题也变成坐标，找最近的几张，再让模型开卷回答。

### 六个核心概念
1. **Embedding**：一段文字→一串浮点数。相似语义往往在向量空间里更接近，不是把文字压缩后无损还原。
2. **Chunk**：卡片大小。太大主题混杂且占上下文；太小丢上下文。
3. **Overlap**：相邻卡片重复一点，降低句子在边界被切断的影响，但增加存储和重复检索。
4. **向量数据库**：保存向量、文本和来源，支持近邻查询。Chroma 不是大模型。
5. **Top-k**：选最相关的 k 个片段。不是越大越好，太大增加噪声、成本、延迟。
6. **RAG**：Retrieval Augmented Generation，先检索，再增强生成提示词；不是微调。

### 代码怎么对应
- documents.parse：TXT/MD 用 UTF-8 解码；PDF 按页提取文字。扫描 PDF 没有文字层时不能直接提取。
- documents.chunks：LangChain 分割器按 600 字符、100 重叠切分；这里按字符而非 token。
- ChromaStore：编码文档和问题，保存 source/page/chunk；余弦距离转成 1-distance，不能当概率。
- RagService.ingest：同名文档替换旧内容，避免重复导入累积。
- RagService.ask：检索→编号→调用 DeepSeek→返回 answer、sources、时间。
- api.py：HTTP 上传和问答入口；/docs 是自动生成的交互 API 文档，不是另做的精美前端。
- evaluate.py：六道样例问答，检查预期证据是否在 top-4，记录时间。

### 向量相似度
余弦相似度 = 两个向量点积 / 各自长度乘积。归一化后点积等于余弦相似度。它衡量向量方向接近，不是“答案有 90% 正确率”。必须用同一个嵌入模型处理文档和问题；换模型后重建索引。

### RAG 与微调
RAG 像临时给资料，适合动态知识和出处追溯。微调像改变答题习惯/行为模式，需要训练数据和训练过程。微调不保证记住每条事实，也不能替代检索中的权限控制。

### 如何判断效果
必须分开看：
1. 解析正确吗？PDF 页码和表格是否丢内容？
2. 召回正确吗？正确证据是否在 top-k？
3. 生成忠实吗？答案每个关键事实能否在证据找到？
4. 引用正确吗？[1] 是否真的支持这句话？
5. 时间和成本如何？拆开记录检索时间、模型时间。

不要把“HTTP 返回 200”称为“问答正确”。本项目提供 evidence_hit_at_4，它是题目级证据命中率，不等于完整多相关文档 Recall@k；六题也不能代表泛化准确率。

### 亲手做一次实验
准备 20–30 道题：直接事实、同义表达、跨段组合、资料不存在的问题。固定语料和模型，分别比较 chunk_size=300/600/1000、k=2/4/6。每次只改一个变量，记录召回和答案依据。若只背“600 最优”却没有实验，面试官一问数据就露馅。

### 已知不足怎么讲
现在是单用户本机原型，没有 OCR、多租户权限、混合检索、reranker、经标定的拒答阈值和并发事务。无答案问题可能也召回相似但无用片段，仍依赖模型拒答。下一步先用真实题集标定，再考虑 BM25+向量混合检索和重排序。

## 5. 高频面试追问：短回答 + 深一层

**Q1：你到底做了什么？**
基于上游 Agent 内核新增了受限工具入口、路径策略、逐次写入和命令审批、步数上限及回归测试；RAG 则实现文档入库、检索、生成 API 和基础评测。循环、会话、压缩、TUI 来自上游，我阅读并运行相应测试。继续追问时打开 UPSTREAM.md 和新增文件。

**Q2：Agent 和普通聊天有什么区别？**
聊天通常给文字答案；Agent 的模型输出可触发程序执行工具，并根据结果继续决策。工具调用是宿主执行，不是模型拥有操作系统权限。

**Q3：为什么不全部用 LangChain？**
第一个项目学习底层调度和安全边界，直接阅读原生循环更透明；第二个复用 LangChain 分割器。没有使用的框架功能不能说做过。

**Q4：如何防死循环和花钱失控？**
新增每个 run 最多 12 次模型调用；还需要任务总时限、token/费用预算和重试预算。只有步数限制不等于完整费用控制。

**Q5：工具报错怎么办？**
工具异常转成结构化错误回给模型，主循环可以继续。认证/配置错误、程序 bug 和用户取消需要区分，不能无限重试或全部吞掉。

**Q6：权限 hook 自己异常怎么办？**
安全校验应默认拒绝。上游 hook 异常隔离和继续执行不等于天然 fail-closed，因此新增路径和审批校验放到工具内部，异常会使工具失败。仍需逐个入口评估。

**Q7：文件搜索会不会泄露密钥？**
新增入口排除 .env 等敏感路径，搜索只在项目内；这不是全能 DLP，密钥放在普通文件里仍可能被读取。应遵循最小权限和不把密钥放项目源码的习惯。

**Q8：shell=False 就安全吗？**
不是。它避免 shell 元字符被再解释，但 `python -c`、脚本和测试仍可执行任意逻辑；最终需要信任、审批及真正隔离的环境。

**Q9：如何保证写入一致性？**
上游有文件修改队列等机制；新增教学工具是简单写入，还没有原子替换与跨进程锁。可增加同目录临时文件+os.replace，并以文件路径粒度加锁。

**Q10：回退会话会回滚代码吗？**
不会，只改变模型看到的对话分支。工作区回滚是另外的问题，需要 Git 或文件快照。

**Q11：压缩为什么保留最近对话？**
最近内容通常包含当前动作和精确细节。摘要降低上下文成本但有信息损失；需要保留约束、决定和工具调用配对。

**Q12：JSON-RPC 为什么需要 id？**
并发或异步返回时匹配请求响应；通知没有 id。传输分帧和异常处理也要实现，JSON 本身不会解决这些问题。

**Q13：怎么测 Agent？**
假模型验证调度、拒绝、异常、恢复和分支；真实 API 验证协议兼容和真实决策；真实任务测成功率、耗时和成本。这三层互相不能替代。

**Q14：RAG 为什么要切块？**
整文档可能超过模型输入预算，向量也难表示多个混合主题。适当分块提高定位精度，但切太小丢上下文。

**Q15：重叠能保证不丢信息吗？**
不能，只缓解边界问题；复杂表格、章节引用和跨页语义仍可能断裂。结构化分块和父子块检索可以改进。

**Q16：检索到了，为什么仍答错？**
可能片段不完整、存在冲突、模型忽略资料或引用错。必须同时评估检索和生成，不要只盯向量相似度。

**Q17：没有相关资料怎么办？**
空库/零命中直接说明无依据；当前向量检索没有经过标定的拒答阈值，所以非空检索仍可能不相关。后续用无答案题集校准。

**Q18：怎么防文档提示词注入？**
资料作为不可信数据，加边界和系统规则；RAG 不暴露执行工具，降低影响面。但提示词不能提供绝对防御，还要做权限过滤、输出校验和攻击样例测试。

**Q19：如何更新文档？**
目前按 source 文件名替换，嵌入成功后删除旧片段并写新片段；这不是原子事务，同名文件可能冲突。生产版本应使用文档 ID、版本号、内容哈希和事务/版本切换。

**Q20：模型变更为什么要重建索引？**
不同模型的维度和语义空间不同，旧文档向量不能随便和新问题向量比较。即使维度相同，也不表示空间相同。

**Q21：能不能多用户使用？**
当前不行。需要认证、文档所有者/租户 metadata，在检索前强制过滤；不能先取到别人的文档再指望模型不说。

**Q22：为什么不用更复杂的 reranker？**
先做可测的基线。reranker 用更贵的模型重新排序候选，可能提升精度但增加延迟；先证明当前错误来自排序而非解析。

**Q23：如何优化响应时间？**
模型常驻、预先计算文档向量、避免重复导入、限制候选和上下文、批量嵌入、缓存稳定查询。先分阶段测时再优化，不能凭感觉。

**Q24：有哪些真正踩过的坑？**
本次实际遇到 GitHub 下载连接重置、Python 临时目录权限错误、依赖下载哈希校验失败。处理分别是连接器按固定提交拉源码、测试临时目录放 D 盘、保留校验并禁用缓存重试。不要说成算法创新。

## 6. 两分钟项目介绍模板

### CodeGuide
“我想理解编程 Agent 如何从一句需求变成文件操作，所以基于 my-pi-agent 做了 CodeGuide。模型通过结构化工具调用提出动作，内核执行后把结果回送，形成 ReAct 循环。上游已有会话树、压缩和终端桥接；我新增了一个便于审查的工具入口，限制项目路径、保护敏感文件、对写入和命令逐次审批，并加入步数限制与测试。通过脚本模型演示真实读写和 pytest 执行。我清楚当前审批不等于沙箱，命令还需要运行在可信项目里。”

### RAG
“我做了面向课程资料的问答原型。PDF/TXT/Markdown 解析后按带重叠的窗口切分，使用 Sentence Transformers 编码并存入 Chroma。查询同样编码，取 top-k 片段给 DeepSeek 生成带来源的回答。API 用 FastAPI，处理了重复导入、输入限制、空库和缺密钥情况。评测把检索命中与生成忠实度分开。目前只有小样例基线，还未完成多用户权限和大规模效果评估。”

最后两段必须按验证报告修正：真实模型尚未验证时就明确说尚未验证；不要照背完成态。
